# Инструкция по устранению бага: зависание кармана при перетаскивании нескольких абзацев текста

## 📌 Описание проблемы
При перетаскивании нескольких абзацев текста с веб-страницы или текстового редактора:
1. Текст не появляется в списке кармана.
2. Счётчик в заголовке (`itemsCount`) увеличивается.
3. Карман «зависает» — после этого в него невозможно ничего добавить до перезапуска приложения.

---

## 🔍 Причины бага

1. **Дублирование `id` в бэкенде Rust:**
   - В `src-tauri/src/models.rs`: метод `StashItem::from_text` генерирует `id` как `format!("{}_text", now)` на основе миллисекунд `now`.
   - В `src-tauri/src/drop_target.rs`: при OLE-дропе текст разбивается на строки через `.lines()`.
   - Если перетаскивается несколько строк/абзацев, в цикле за одну и ту же миллисекунду создаются элементы с **одинаковыми ID**.

2. **Фатальный сбой рендеринга Svelte 5:**
   - В `src/App.svelte`: список рендерится через `{#each items as item (item.id)}`.
   - При наличии дубликатов ключей рантайм Svelte 5 выбрасывает ошибку `keyed_each_duplicate`.
   - Счётчик в шапке (находится выше в шаблоне) успевает обновиться, но рендеринг списка падает, дерево реактивности ломается, и компонент перестаёт принимать новые события.

3. **Некорректная логика дробления текста:**
   - Перетаскивание связного фрагмента текста (нескольких абзацев статьи) сейчас ошибочно нарезается на множество отдельных карточек, хотя пользователь ожидает одну текстовую заметку.

---

## 🛠 Пошаговый план исправления

### Шаг 1. Гарантия уникальности ID в `src-tauri/src/models.rs`
1. Подключить атомарный счётчик:
   ```rust
   use std::sync::atomic::{AtomicU64, Ordering};
   static ID_COUNTER: AtomicU64 = AtomicU64::new(1);
   ```
2. В `StashItem::from_text` и `StashItem::from_path`:
   - Включать значение счётчика в `id`:
     ```rust
     let count = ID_COUNTER.fetch_add(1, Ordering::Relaxed);
     // для text:
     id: format!("{}_{}_text", now, count),
     // для path:
     id: format!("{}_{}_{}", now, count, sanitize_id(&name)),
     ```

### Шаг 2. Корректная обработка текста в `src-tauri/src/drop_target.rs`
Не дробить любой многострочный текст на строки:
1. Проверять: если все непустые строки являются валидными URL (`http://` или `https://`), только тогда создавать по карточке на каждый URL.
2. Если это обычный текст (даже с переносами строк):
   - Добавлять его как **один единый `StashItem::from_text(&text)`**.
   - `from_text` должен сохранять весь переданный текст с переносами строк в `text_preview`.
   - В качестве имени `name` брать первую непустую строку (первые 25–30 символов).

### Шаг 3. Корректная обработка в `src/App.svelte`
1. В функции `handleContainerDrop`:
   - Убрать цикл `for (const line of lines) await invoke("add_stash_text", { text: line })`.
   - Если перетащен текст (не список URL), вызывать команду один раз:
     ```typescript
     items = await invoke<StashItem[]>("add_stash_text", { text: contentToAdd.trim() });
     syncSelectionWithItems();
     ```
2. В шаблоне списка:
   - В блоке `{#each}` обеспечить безопасный составной ключ или защиту от дубликатов:
     ```svelte
     {#each items as item, index (item.id ?? `${index}`)}
     ```

## ✅ Критерии приёмки (DoD)
- [ ] Выделение и перетаскивание 2+ абзацев с веб-страницы создаёт одну аккуратную текстовую заметку в кармане.
- [ ] Если перетаскивается пачка ссылок (каждая строка — URL), создаются отдельные элементы для каждой ссылки без дублирования `id`.
- [ ] В консоли нет ошибок `keyed_each_duplicate`.
- [ ] После добавления многострочного текста карман продолжает штатно принимать новые файлы и текст без перезапуска приложения.
- [ ] Потребление памяти остаётся строго в пределах Kobalt Tools Standard (до 25 МБ RAM).
